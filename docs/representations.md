# Inscriptions and textual works

The unpublished Akousmata 0.9.0 candidate reads retained representations from
the canonical shared Earworm store. Sources, received projections, accounts and
complete works retain their separate identities. Binary MIDI sources remain
registries; their textual event views are separate artifacts. Original layout
and authorship remain available without an audio player or rendered sound.

The private `/inscriptions` reader links from the library header. It lists
permitted records, shows exact text and current access, and displays convention,
coverage, transformations and return context. Supplied text is inserted as text,
never executable HTML or code. Artifact downloads are attachments with
`application/octet-stream` and `nosniff` headers.
Adopted context can be expanded in full beside the source and finished work.

Metadata search, form and output filters share bounded continuation with the
other owners. Older records remain reachable beyond 200, including through
empty pages. Tokens bind the exact query and current owner audience, expire
after 15 minutes and reveal no denied identities or totals. Refresh begins at
the newest permitted page.

The private browser copy has a 30-second access lease. Failed reads, expiry,
hidden pages and changed owner bindings clear the list and detail. A new
selection aborts older requests; late replies cannot replace it. Every action
checks the owner identity before and after its payload. Requests time out after
10 seconds. Refresh checks current permission; it does not delete or rewrite
the retained artifact. Source text stays inert throughout this lifecycle.

The versioned `/api/representations` interface supports record queries, detail,
exact artifact retrieval, byte comparison, selected export and prepared returns.
It keeps the existing owner request boundary and workspace generation checks.
Legacy audio detail, projections and publication helpers refuse this record
family. They cannot infer public permission from an audio consent field.

Export requires an explicit artifact selection and current owner or public
export uses. Its projection includes only selected artifacts, their applicable
outputs and relations whose ends are both selected. An omission count makes
the selection visible. It does not rewrite the canonical record or remove
inherited terms. Public export is a separate explicit API request; the private
reader offers owner export only.

A prepared revisit selects the exact previous original or completed output and
declares independent, informed, shared-analysis or unknown context. Informed or
shared returns need explicit prior accounts; an independent return cannot
include them. Current read and execution uses are checked. Preparation calls no
provider, adopts no profile and defaults to no retention. Oída receives the
request only after provider, model, scope and applicable authority are selected.
Khipu's local candidate provides integrated source selection, explicit text
execution and History/Station readers. Phase 10 reconciled and checked the
candidate owner cohort in an isolated offline installation. This did not replace
an active owner installation or publish the candidate.

Metadata and content are separate permissions. Withheld content is displayed as
unavailable while permitted metadata can remain visible. Revoked metadata hides
the record from versioned queries. Finished works can become new primary inputs
without a required acoustic conversion. The candidate remains local and has
not changed an active owner installation.
